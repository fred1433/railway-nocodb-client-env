Limits and decisions

  1. Private tunnel rather than a public Railway domain: a second public path would go around Access.
  2. Access in front of NocoDB Community leaves a second login: a token that passes Access still gets HTTP 401 from NocoDB.
  3. Since 9 January 2026 the NocoDB license reads: "Internal self-hosting does not require a commercial license", while a commercial license is needed to "Provide direct NocoDB access to external customers". The question is who uses NocoDB, and who owns the instances.
  4. QuickBooks OAuth redirects and webhooks do not go through an interactive login, and Intuit signs its webhooks. They need their own route.
  5. Read-only NocoDB is a choice for this example, not a rule of the setup. Edits would need a role with write grants.
  6. On NocoDB 2026.10.1, NC_INVITE_ONLY_SIGNUP=true left sign-up open on the first run (HTTP 200). The bootstrap now sets the admin setting and checks it before the tunnel starts.
  7. NocoDB 2026.10.1 reached 0.99 GB in these two environments and rested near 0.72 GB. It did not start under a 512 MB limit in the settings tried.
  8. Railway cron schedules are in UTC, so the local time of a backup moves with daylight saving.
  9. Outside this example: real QuickBooks, a GitHub organization per client, n8n.
